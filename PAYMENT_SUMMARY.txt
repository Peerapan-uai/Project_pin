1. OVERVIEW
================================================================================

ระบบการชำระเงิน (Payment System) สำหรับแอปพลิเคชัน EV Charger App ที่รองรับ:

• PromptPay QR Code    — สแกน QR + Transfer ผ่าน Mobile Banking
• Credit Card/Debit    — Charge ผ่าน Omise payment gateway (รองรับ 3D Secure)
• Wallet              — ระบบกระเป๋าเงิน (อาจเพิ่มในอนาคต)

2. API ENDPOINTS — รวม 17 ตัว
================================================================================

EXISTING (nem's responsibility) — 3 ตัว:
  1. POST   /api/payments                → Create payment
  2. GET    /api/payments/history        → Get history
  3. GET    /api/payments/{id}           → Get single

NEW ENDPOINTS (ต้องสร้าง) — 14 ตัว:

Payment Processing — 4 ตัว:
  4. POST   /api/payments/qr             → Generate PromptPay QR
  5. POST   /api/payments/charge         → Charge credit card (Omise)
  6. GET    /api/payments/{id}/status    → Check status (polling)
  7. POST   /api/payments/{id}/confirm   → User confirm (optional)

Webhooks — 2 ตัว:
  8. POST   /api/payments/webhook/promptpay  → PromptPay/Bank webhook
  9. POST   /api/payments/webhook/omise      → Omise webhook

Admin — 5 ตัว:
  10. GET   /api/payments/admin/all       → View all payments
  11. GET   /api/payments/admin/{id}      → View payment detail
  12. PATCH /api/payments/{id}/refund     → Admin refund
  13. GET   /api/payments/admin/refunds   → View refund history
  14. GET   /api/payments/admin/stats     → Payment statistics

Cron Jobs (Internal) — 3 ตัว:
  15. Every 1 min  → Cleanup pending (timeout > 15 min)
  16. Every 5 min  → Retry failed webhooks (max 3x)
  17. Every 10 min → Sync payment status with provider

3. PAYMENT FLOWS — 3 Main Scenarios
================================================================================

SCENARIO 1: PromptPay QR Code
├─ User charges → Payment page
├─ Select PromptPay → Generate QR
├─ Frontend POST /api/payments/qr
├─ Backend creates payment (pending) + calls PromptPay API
├─ Frontend shows QR + timer (10 min)
├─ Frontend polls GET /status every 3-5 sec
├─ User scans QR + transfers money via Mobile Banking
├─ Bank sends POST /webhook/promptpay
├─ Backend verifies signature → UPDATE status='completed'
├─ Frontend detects completion → Show success
└─ Expected time: 15-30 seconds

SCENARIO 2: Credit Card (Omise)
├─ User charges → Payment page
├─ Select Credit Card → Show card form
├─ Frontend tokenizes card with Omise.js
├─ Frontend POST /api/payments/charge { token, ... }
├─ Backend creates payment + calls Omise API
├─ 3 response cases:
│  ├─ Non-3D: Successful → UPDATE status='completed'
│  ├─ 3D Required: Pending → Frontend redirects to 3D page
│  │  → User enters OTP → Bank webhook confirms
│  └─ Decline: Failed → UPDATE status='failed' + show error
├─ Frontend shows result (success/pending/failed)
└─ Expected time: 5-10 sec (non-3D) or 2-5 min (3D)

SCENARIO 3: Admin Refund
├─ Admin views payment dashboard
├─ Click [Refund] button for completed payment
├─ Show refund form (amount + reason)
├─ Admin enters details → Click [Process Refund]
├─ Frontend PATCH /api/payments/{id}/refund
├─ Backend creates refund record
├─ Backend calls Omise refund API (if credit card)
├─ UPDATE payment.status='refunded'
├─ Send notification to user
└─ Expected time: 30-60 seconds

5. SECURITY MEASURES
================================================================================

✓ Signature Verification
  - HMAC-SHA256 for PromptPay webhook
  - HMAC-SHA256 for Omise webhook
  - Reject invalid signatures (401 Unauthorized)

✓ Double Charge Prevention
  - UNIQUE constraint on transaction_ref
  - Check if payment exists before creation
  - Database row-level locking (FOR UPDATE)

✓ Webhook Idempotency
  - webhook_received flag in DB
  - Skip if already processed
  - Return 200 OK (no error)

✓ Timeout Handling
  - QR expires: 10 minutes
  - Card 3D: 15 minutes
  - Pending payment: 15 minutes total
  - Cron job marks expired as 'failed'

✓ Card Data Protection
  - NEVER store card data
  - Use Omise tokenization
  - PCI DSS compliant

✓ Webhook Retry Logic
  - Failed webhook? Retry up to 3 times
  - Exponential backoff: 5s → 10s → 20s
  - Alert admin if still failing

================================================================================
6. ERROR SCENARIOS
================================================================================

QR Timeout:
  └─ Pending > 15 min → Cron marks 'failed' → Notification

Card Declined:
  └─ Omise returns failed → Show error → User can retry

Webhook Failure:
  └─ Webhook down? → Polling + Cron retry → Eventually succeeds

3D Secure Timeout:
  └─ User timeout on 3D page → Status stays pending → Can retry

Double Charge:
  └─ Duplicate request? → UNIQUE constraint rejects → Return 400

Webhook Signature Attack:
  └─ Invalid signature → Return 401 → Log incident → Alert admin
